--- addendum: the published help text, raw ---
$ otter start --help   (excerpt)
Usage: otter start [flags]

Starts the runtime for the project containing the working directory:
its jobs are the project, its state lives in .otter/data, and
it records the address it binds so every other command finds it.

otter.env and otter.daemon.env at the project root are loaded first;
a variable already set in the environment wins over the file.

The daemon's own flags are accepted and forwarded, so --workers,
--log-format, --api-token and the rest work here too.

Flags:
  -allow-incomplete-recovery
    	start even when crash recovery or queue reconciliation fails
  -api-token string
    	bearer token required for API access
  -capture-default string
    	HTTP capture policy for runs that do not choose one: off, metadata or full
  -capture-retention duration
    	how long captured HTTP payloads are kept (0 disables expiry)
  -data string
    	data directory holding otter.db and the extracted SDK (default "./tmp")
  -detach
    	run in the background and return once the API answers
  -jobs string
    	directory scanned recursively for otter.yaml (default "./jobs")
  -listen string
    	HTTP API listen address; default picks a free loopback port
  -log-format string

So the loss is specific to --detach: foreground start calls daemonArgs() and forwards the flag;
startDetached() rebuilds the child argv from jobs/data/listen plus trailing passthrough only
(internal/cli/start.go:426-430) and drops every other parsed flag.
