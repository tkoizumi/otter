--- why the host was rebuilt ---
The first host had no swap and no provisioning report. The stack user-data ran
`set -euo pipefail` and then `systemctl reload ssh || systemctl reload sshd`, which fails
on Ubuntu 24.04 because sshd is socket-activated; the abort skipped the swap block and
the report. Fixing that exposed a second instance of the same mistake: the `sshd -t`
validation added in its place exits 255 with "Missing privilege separation directory:
/run/sshd" on a first boot, before anything has connected. Reproduced locally in
otter-deploy-target: 255 without /run/sshd, 0 after `install -d -m 0755 /run/sshd`.
Both are fixed, and both now have regression tests that go red when reverted.

Worth knowing for any future deploy: the version a host reports comes from the CLI binary
you run, not from the checkout you compile, so `make build VERSION=` must precede a deploy
whose label matters.

FAILED (5). Three of the five are the script is wrong, not the host:

  - otter.db is mode 644, want owner-only          [expectation beyond the bar]
  - otter.db-wal is mode 644, want owner-only
  - otter.db-shm is mode 644, want owner-only
        The data directory is 700 otter:otter and no other account can enter it, so the
        file mode is contained. The task requires the DIRECTORY to be 0700, which it is.
        A tighter umask would give 600 and is a fair defence-in-depth suggestion, but
        failing a host that meets the stated requirement is the wrong response.

  - /etc/otter/workspaces/<ws>.env is owned by root:root, want otter:otter
  - /etc/otter/workspaces/<ws>.daemon.env is owned by root:root, want otter:otter
        This one is backwards, and satisfying it would make the host LESS safe.
        Measured: /etc/otter/workspaces is 700 root:root, both env files are 600 root:root,
        and the otter account CANNOT read its own credentials file. systemd reads
        EnvironmentFile= as root before dropping to User=otter. P0-12 independently
        verified this shape (umask 077, 0700 env dir, root-owned 0600 file). Making the
        service account the owner would let it -- and any compromised job -- rewrite its
        own credentials. The assertion encodes an outdated line in phase-0-tasks.md
        ("environment file 0600, owned by the service account"), which is the thing to
        reconcile; the host is right.
