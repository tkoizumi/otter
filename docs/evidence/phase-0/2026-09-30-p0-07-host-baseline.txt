--- FINDING: cloud-init failed; the host was left missing its swap ---
cloud-init status: error
  errors: ('scripts_user', RuntimeError('Runparts: 1 failures (part-001) in 1 attempted commands'))

The user-data script sets `set -euo pipefail` and runs:

    systemctl reload ssh || systemctl reload sshd

On Ubuntu 24.04 sshd is socket-activated. The provision log records:

    ssh.service is not active, cannot reload.
    Failed to reload sshd.service: Unit sshd.service not found.

Both sides of the `||` fail, so `set -e` aborts the script -- before the swap block,
the vm.swappiness write, and the provisioning report were reached.

Consequences observed:
  - Swap: 0 MiB (the stack declares enableSwap: true and otter-platform/README.md
    treats the 2 GiB swapfile as part of the 1 GiB sizing rationale).
  - /var/log/otter-provision-report.txt does not exist, so the documented first-run
    step `cat /var/log/otter-provision-report.txt` fails.
  - vm.swappiness was never set.
  - SSH hardening did apply: the config file is written before the reload, and a
    socket-activated sshd re-reads config per connection. sshd -T confirms
    permitrootlogin no, passwordauthentication no, permitemptypasswords no.

Converged manually (not by the provisioning script), to restore the declared state:
  - /swapfile 2 GiB, mkswap, swapon, added to /etc/fstab  -> Swap: 2047 MiB
  - /etc/sysctl.d/99-otter-swap.conf vm.swappiness=10

Deliberately NOT converged: the provisioning report. That file is the provisioning
script's own output, and writing it by hand would fabricate evidence for the very
step that failed. It stays absent until the user-data bug is fixed.

The defect is in otter-platform (the CDK stack user-data), not in this repository.
The user-data comment also says "a 2 GiB host", which is stale: this host is 1 GiB.
