--- P0-10 crux: two alarms, one synthetic metric, identical conditions ------------
Two alarms in the otter account, no actions attached (so nothing could be mailed),
same namespace/metric/dimension/statistic/period/evaluation, differing only in the
evaluation window. Six datapoints were published, both arms settled OK, publishes
stopped, and CloudWatch's own state history timed each arm from the last datapoint.

  arm               window              last datapoint      OK->ALARM            latency
  verify-sliding    default (sliding)   2026-09-30T22:30Z   2026-09-30T22:41:57Z 11m57s
  verify-walled     WallClockWindow     2026-09-30T22:30Z   2026-09-30T22:36:39Z  6m39s

This reproduces the host drill's 11m10s vs 5m34s on a different metric with no host,
no daemon and no config change between arms. The wall-clock window is what makes
`Period 60s x 5` mean roughly five minutes; the default sliding window ignores the
missing-data treatment while it can still find real datapoints and takes about
twice as long. Both verification alarms were deleted afterwards.

--- defect found ---------------------------------------------------------------
D1  install-monitoring.sh: the convergence probe can never report a converged host.
    The probe (scripts/install-monitoring.sh:355-371) tests `/etc/otter/heartbeat.env`
    and `/etc/otter/disk-check.env` with a plain `[ -f ]` run as the ssh user, but
    `/etc/otter` is `drwxr-x--- root root`. The files exist and the units load them
    (`EnvironmentFiles=/etc/otter/heartbeat.env (ignore_errors=no)`); the probe just
    cannot see them, so `probe_out` is never empty, `already=0` always holds, and
    every run reports "not yet converged: /etc/otter/heartbeat.env(missing)
    /etc/otter/disk-check.env(missing)" and reinstalls.
    Reproduced three times against the live host, at commit d03dbeb.
    Harmless in behaviour (the install is idempotent and the assertions still run),
    but the convergence claim is false, and its suite cannot see it: the fixture
    intercepts the whole probe (`match *# install-monitoring-probe*`) and returns
    whatever each case wants, so the probe's logic never executes, and the
    "a converged host reports convergence" case asserts only how the installer handles
    an empty result. Claim and test are both about a probe that was never exercised --
    the fixture-contradicts-reality class of P0-03's D1/D2/D5. Filed as OT-022.
    Fix: read those two files under privilege (`[ "$(id -u)" = 0 ]` or `sudo -n`) and
    stop stubbing the probe wholesale, so the permission-sensitive lines run against a
    fixture that models a 0750 directory the login cannot read.
