## ROUND 3 — verdict

* uv 0.5.9 records the root-slash form for a bare-host index and accepts either
  spelling; it removes dot segments; it does not decode percent escapes and does
  not fold a non-empty trailing slash. otter now folds exactly that set, so it
  accepts what uv accepts (bare host, dot segments) and refuses what uv refuses
  (trailing slash, percent escape).
* The mismatch hint's advice terminates: `uv lock --default-index <configured>`
  produces the canonical spelling this check compares
  (TestRelockingAgainstTheConfiguredIndexIsAccepted, demo case 3).
* With a lock that records a registry, UV_INDEX, UV_EXTRA_INDEX_URL and
  UV_FIND_LINKS each turn a working sync into uv's bare lockfile exit 2
  (measured, one case each), so otter refuses them and names the variable before
  any fetch. UV_NO_INDEX was measured to change nothing there, and a lock with no
  registry package has no source an index could change, so neither is refused.

  depends on this comparison modelling uv perfectly.

## ROUND 5 — verdict

* The empty fragment is refused, so no measured pair remains where otter
  accepts what uv refuses: the under-refusal class is closed. The comparison
  folds what uv was measured to fold (host case, credentials, default and
  leading-zero ports, backslashes, empty paths, literal and percent-encoded dot
  segments including a lone `%2e`, and the IPv4 spellings including hex, octal
  and percent-encoded hosts) and refuses what uv refuses (scheme case, trailing
  slash, empty query, empty fragment, escape case, doubled slash, `...`).
* The additive hint has no looping remedy: omitting the variable always
  satisfies --locked, and re-locking is offered only for a source that really
  supplies packages, which is when uv records it. The conservatism is stated at
  the refusal ("otter cannot tell from the lock whether this source would change
  the resolution") and in the comment there.
* The pairs otter refuses although uv accepts are listed in
  TestDeliberateConservativeDivergences -- a harmless unrecorded added source
  (three variables) and a Unicode IDNA host -- so a future fix edits that table
  instead of turning a "uv behaves like this" assertion red. The unrecorded-
  source refusal itself is now guarded at the Prepare level, which is the gap
  the round-4 verification found.
* uv's name=url index spelling is unwrapped, so the one route otter cannot see
  through a config file is no longer over-refused.

## VERDICT

* uv 0.5.9 refuses a configured index that differs from the lock's recorded
  registry (e2, e3, e5: exit 2) even when the artifact is byte-identical, and
  does not fold a trailing slash (e5); it does fold host case (e6). With no
  index configured it installs from the URL the lock records (the no-index
  capture above), so a mirror-cut lock needs no flag and a PyPI-locked project
  cannot be redirected without re-locking.
* otter refuses that pairing before anything is fetched, naming the lock, the
  index it records and the index configured, and its preflight checks the
  registries the lock records when nothing is configured.
* Every assertion above has a mutation that makes it go red; the route reaches
  uv's real argv in the tests and uv's real behavior in the UV section.
* The two drills that stub uv (`backup-restore`, `deploy-failure`) still pass,
  and the injected failure is the stub refusing, not the preflight.
* Round 3 refined the comparison and the additive-source handling; see its
  verdict above for what the second verification changed.
