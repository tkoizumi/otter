# Otter v0.5.1 — Ubuntu packages

Status: release notes. Date: 2026-10-07. Previous release: `v0.5.0`.

`v0.5.1` adds a Debian package to the release artifacts. `v0.5.0` shipped
tarballs only, so a Linux install meant downloading an archive and placing two
binaries by hand: nothing could upgrade them and nothing could remove them.

Read this first:

- **The `.deb` installs `otter` and `otterd` into `/usr/bin`.** If you already
  put them on your `PATH` from a tarball — `~/.local/bin`, most likely — your
  shell may keep resolving that copy, because it comes first in `PATH`. Remove
  it, or leave its directory later in `PATH`, or `otter version` will disagree
  with `dpkg -l otter`.
- **macOS is unchanged.** The cask in the tap still installs the tarballs, and
  this release updates it to `0.5.1` in step.

## Installing on Ubuntu

```sh
curl -LO https://github.com/tkoizumi/otter/releases/download/v0.5.1/otter_0.5.1_linux_amd64.deb
sudo apt install ./otter_0.5.1_linux_amd64.deb
```

`apt` records the package, so `apt remove otter` works, and the two binaries are
versioned with the rest of the system rather than living in a home directory.

Nothing else changes in this release: no runtime, protocol or manifest surface
is touched, and no migration runs.

## What this is not yet

A hosted APT repository. There is no `otter` package in an archive you can
`apt install otter` from by name, and no signing key to trust — so upgrades do
not flow through `apt upgrade` yet, and each release is still a download from the
release page. That repository is the next step; this release is the artifact it
will carry.
