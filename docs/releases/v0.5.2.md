# Otter v0.5.2 — Deploy what you released

Status: release notes. Date: 2026-10-07. Previous release: `v0.5.1`.

`v0.5.2` makes `otter deploy --cloud` promote a release you already made, rather
than packaging the working directory as it goes, and adds job deletion. Deploy
stops being a build; release becomes the build.

Read this first:

- **`otter deploy --cloud` changed meaning.** It promotes the **latest local
  release** for the job. Editing a job and deploying no longer ships the edit —
  run `otter release` first. `--build` restores the previous behaviour, packaging
  the workspace as part of the deploy.
- **Name a release when you don't want the latest.** `--release <digest>` takes
  bare hex or `sha256:<hex>`; `--release latest` is the default spelled out.
  `otter release --list` shows the digests with their creation times, and "latest"
  is the newest by creation time.
- **The prepared environment is frozen at release time.** A job using
  `python.mode: managed` prepares its interpreter and locked dependencies when you
  release, and those ship inside the release. Release on the platform the runtime
  runs on — a release built on macOS carries a macOS environment.
- **Deleting a job is new, and it is destructive.** It removes the job's state,
  runs and logs, captured payloads, schedules, configuration and every release,
  including the active one. It refuses while a run is in flight.

## Deploying

```sh
cd <job directory>
otter release                 # build the artifact; prints its digest
otter deploy --cloud          # promote the latest release
otter deploy --cloud --dry-run   # say what would go, send nothing
```

`otter deploy --cloud --release <digest>` promotes a specific release, which is
also how a rollback is expressed: promote the digest you were on before. A release
Cloud does not already hold is uploaded first — a copy, not a build, so no
preparation is involved and the digest cannot change on the way.

`otter deploy --host <user@host>` is unchanged: it is a converge that ships the
source tree for every job, and it neither requires nor produces a release.

## Deleting a job

```sh
otter delete <job>            # locally
```

This is also available against a pooled runtime from Otter Cloud
(`DELETE /api/jobs/{id}`, a `deploy`-scoped operation). What it removes: state,
runs and logs, captured payloads, the webhook token, pause, schedules, job
configuration, and every staged release including the active link.

Two things worth knowing before using it:

- **A job with a run in flight is refused** (409, naming the run) and nothing is
  removed. Cancel the run first. The check runs before any store write, so a
  refusal is never a partial delete.
- **A job that exists only as a release has no tombstone.** A workspace job keeps
  its source and is remembered as deleted; a job known only from its releases is
  removed outright, so staging and activating a new release for the same job id
  makes it reappear. The response says so rather than leaving you to discover it.

Deleting a **dedicated** (non-pooled) runtime's job is refused: the runtime's own
delete is admin-only, and Cloud holds no admin credential by design.

## Fixes

- **Job detail pages in Otter Cloud reported every job as unavailable.** The
  transport asked the agent for a `job.get` read, which is not one of the reads
  the agent is allowed to perform; a single job is meant to be narrowed out of
  `jobs.list`. The job *list* worked throughout, which is why only the detail page
  was empty. Fixed in Cloud; no CLI change.
- The README's install section and the changelog index had fallen behind the
  releases: the section offered only Homebrew, with no Linux path and no mention
  that `apt install otter` by name does not exist yet.

## Known limitations

- `otter deploy --cloud` reports `upload: needed` even for a release Cloud
  already holds. The presence probe (`GET /api/releases/<digest>`) is not served
  by the control plane yet, so the client cannot confirm presence and uploads
  idempotently. The upload is harmless; the report is imprecise.
